ACTIVITY ACKNOWLEDGMENT / 03

The scene pauses for you.

The reward is a character noticing your effort. Not another location, an extra plot step, a secret, or a collection counter.

Three cast situations

  • Lyra: a knowing look and a small approving smile at the console.
  • Lyra + Doc: both acknowledge you from their existing positions.
  • A private aside: Lyra looks toward you during the pod scene. The Listener stays occupied and unchanged.

These are three matched scene studies, not three competing reward systems and not a new fourteen-panel art set. The main page replaces the earlier experiment; its full story and mechanics remain in the earlier reward study.

What changes

The acknowledgment uses a generated facial-acting edit to the displayed base artwork. Only local head and neck regions are composited back. Scenery, camera, body positions and the graphic header remain unchanged. There is no darkening filter, zoom, exercise pose or animated morph.

The base images are the existing graphic review candidates for panels 1, 3 and 11, not a claim that these precise compositions are already shipped. The acknowledgment returns to the exact same displayed base image.

A recorded Garmin workout gets exercise praise, with no guessed sport, duration prefix or inferred achievement. A known walk or run includes its distance and activity: “Great 5K walk!” or “5K run? Bravo!” Four authored lines per category and scene give 36 caption templates. All supported preview values fit the existing 16-character caption limit.

New acknowledgment artwork was generated for all three scenes in this revision. The refresh control cycles wording only; it does not imply a separate image for each line. Repeated acknowledgments also cycle the wording, while the selected line stays stable during a displayed moment.

Authored, not random

Choose who acknowledges the reader per scene. A friendly companion may join in; an antagonist must not. Keep a restrained expression in serious scenes. A character's attention changes briefly, not their role in the story. This page tests the effect; it does not implement cast-selection logic.

Prototype boundaries

The watches are repeatable before/after comparisons, not a live activity detector or a simulated daily reward ledger. Acknowledgment and resume are manual, with no real two-hour wait. No Garmin runtime was changed.

The workout control now represents only “Garmin workout recorded”. There is no duration input or sport inference. Walk/run distance controls retain the current 3 km threshold, with a 99 km preview maximum. This is an acknowledgment preview, not a new activity-detection engine.

The unchanged production code currently uses a 15-minute threshold for eligible generic workouts, plus a step-walk fallback, one reward per day and a two-hour reward window. Whether to remove that existing duration threshold from production is a separate implementation decision; the preview does not alter it or claim that change has shipped.

Returning to the same story panel is a proposal: today the runtime advances one extra panel when the action expires. This preview does not set a new duration, remove the daily cap or promise instantaneous detection.

Browser overlays use an approximate font and fixed sample watch data. Physical Garmin legibility, memory and bitmap conversion still need testing before any production adoption.
